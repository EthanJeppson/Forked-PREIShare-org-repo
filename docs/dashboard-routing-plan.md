# PREIshare Dashboard Routing Plan

## Purpose

Map the investor dashboard URLs to TanStack Start route files before any UI is generated. This plan names the files to create later. It creates none of them.

Source requirements: `docs/investor-dashboard-brief.md`. That file is this repo's requirements brief for the dashboard; no file named `docs/preishare-dashboard-requirements.md` exists in the repo. Related plans: `docs/dashboard-ia.md` (pages and nav labels) and `docs/component-plan.md` (components).

## Planned dashboard route tree

```text
/                          existing  src/routes/index.tsx
/about                     existing  src/routes/about.tsx
/dashboard                 layout    shared dashboard shell, renders child pages through an Outlet
  /dashboard (index)       page      Overview: stats, portfolio summary, recent activity
  /dashboard/portfolio     page      Portfolio: holdings table
  /dashboard/deals         page      Deals: open deals list
  /dashboard/profile       page      Profile: read-only member card
```

Four child pages, matching the four areas in the brief. There is no `/dashboard/activity` page. Recent activity is a list on the Overview page, and the brief rules out extra product areas.

## File map (exact files to create in a later step)

| URL | Role | File to create | Route id it declares | Wraps / renders |
| --- | --- | --- | --- | --- |
| `/dashboard` | Layout route | `src/routes/dashboard/route.tsx` | `/dashboard` | Shared dashboard shell; renders the matched child via `<Outlet />` |
| `/dashboard` | Index page | `src/routes/dashboard/index.tsx` | `/dashboard/` | Overview content |
| `/dashboard/portfolio` | Child page | `src/routes/dashboard/portfolio.tsx` | `/dashboard/portfolio` | Portfolio content |
| `/dashboard/deals` | Child page | `src/routes/dashboard/deals.tsx` | `/dashboard/deals` | Deals content |
| `/dashboard/profile` | Child page | `src/routes/dashboard/profile.tsx` | `/dashboard/profile` | Profile content |

Conventions this relies on (checked by running the route generator on a scratch copy; no files in this repo were touched):

- Inside a folder, `route.tsx` becomes the layout route for that folder's path, and the other files become its children.
- `index.tsx` is the default child. Its route id ends with a slash (`/dashboard/`), while its URL is `/dashboard`.
- `src/routeTree.gen.ts` is regenerated by the dev server or `npm run generate-routes`.

`docs/dashboard-ia.md` previously sketched flat file names (`dashboard.tsx`, `dashboard.index.tsx`, and so on). This plan replaces that sketch with the folder form above. The URLs are the same.

## Layout vs page responsibilities

- **Layout (`dashboard/route.tsx`)**: the persistent shell only. It holds the places for the sidebar, the header, and the main content (the Outlet). It has no metrics, holdings, deals, or profile content, and it does not hold mock data.
- **Index (`dashboard/index.tsx`)**: the Overview home content only. It uses the parent layout and does not repeat the sidebar or header.
- **Child pages (`portfolio`, `deals`, `profile`)**: each owns only its own main-region content and renders inside the same layout. Switching between them changes the main region, not the sidebar or header.
- **Placeholders for the first build**: each child can start as a title plus a short "coming soon" line, so navigation links have real targets. Full content comes in later steps.

## Navigation labels (for sidebar / mobile nav later)

| Label | Path | Requirement link (`docs/investor-dashboard-brief.md`) |
| --- | --- | --- |
| Overview | `/dashboard` | Goal 1: open the dashboard and see a home overview with a portfolio snapshot and recent activity |
| Portfolio | `/dashboard/portfolio` | Must-have area "Portfolio"; goal: scan portfolio value and holdings |
| Deals | `/dashboard/deals` | Must-have area "Deals"; goal 3: see which deals are open |
| Profile | `/dashboard/profile` | Must-have area "Profile"; goal 4: check who they are in PREIshare |

Goal 2 (reach Portfolio, Deals, and Profile without typing a URL) is met by the four labels together appearing as persistent navigation on every dashboard page. The single place that holds these labels and paths is `navConfig` in `docs/component-plan.md`.

## Out of scope for this plan

- Component props, component code, and styling (the component plan and UI steps)
- Authentication, route guards, redirects for signed-out visitors
- Loaders, server functions, and any Supabase or database queries (mock data only this sprint)
- API routes
- Extra pages: activity, settings, notifications, login, admin
- Changing or deleting `/`, `/about`, or `__root.tsx`

## Success criteria for implementation steps

- Visiting `/dashboard` shows the dashboard layout with the Overview content in the main region.
- `/dashboard/portfolio`, `/dashboard/deals`, and `/dashboard/profile` each render inside the same layout; the shell does not disappear or reload as a separate page.
- Exactly five new route files exist under `src/routes/dashboard/`, and `src/routeTree.gen.ts` was regenerated, not hand-edited.
- `/` and `/about` still load, and no existing route file was deleted.
- `npm run typecheck` and `npm run build` pass.

## Open questions

- **Root header and footer.** `__root.tsx` renders the site `<Header />` and `<Footer />` on every page, so `/dashboard` pages would show the site header above the dashboard shell. Decide in a later step whether the dashboard should keep them, hide them for `/dashboard/*`, or move them into a separate layout route. This is the biggest risk of two headers on one screen.
- Should the site header or the starter home page link to `/dashboard`? The brief leaves this open.
- Should `/dashboard` ever redirect signed-out visitors once authentication exists? Out of scope now, but it affects whether the layout route later needs a guard.
- If a requirements file named `docs/preishare-dashboard-requirements.md` is expected by a later step, create or rename it deliberately; this plan assumes `docs/investor-dashboard-brief.md` is the intended file.
